# Communication Preferences

- Communicates in Chinese and wants user-facing text/menus in Chinese; when asking for AI prompts/skill content, often specifically wants an English version. Confidence: 0.85
- Frequently asks for generated commands/prompts to be copied directly to the clipboard ("直接复制到我的剪切板"). Confidence: 0.7
- Prefers diagnosing by pasting concrete logs/commands and pointing to specific servers/devices rather than generic descriptions. Confidence: 0.7
- Reports bugs as numbered lists of observed symptoms (including which UI evidence contradicts the seeming conclusion, e.g. "stop button is still showing so it likely hasn't finished") and asks for root-cause investigation ("排查一下…看看是为啥") rather than an immediate fix; often explicitly forbids touching code until the cause is found ("不要改代码，先排查") and wants a thorough investigation of the whole relevant path ("全面地排查一下"). Confidence: 0.75
- When reporting a new bug/symptom, wants the agent to first demonstrate it has correctly understood the problem — restating the exact trigger scenario and asking clarifying questions when the conditions are ambiguous — before digging into the code or proposing a fix ("你先排查一下，理解一下我的问题"). Confidence: 0.6
- Pings mid-task with short status checks ("搞定了吗", "修好没有？", "排查出来为什么了吗？"), sometimes repeating the same question while the work is still running, and expects a direct done/not-done answer — including an honest "not yet" with the current blocker and what has actually been verified — instead of a long narrative or an implied completion. Confidence: 0.7
- Gets openly impatient when long-running work (e.g. a release) runs far past the expected time, asking what the agent is even doing and pointing back at the existing workflow ("干了三十分钟了都没干好，不是有部署流程吗") — so they want proactive progress reporting while a long task runs, not a silent wait, plus a concrete accounting of where the time went if it overruns. Confidence: 0.6
- After a batch of feature requests, asks for confirmation that everything they asked for is actually implemented ("我要的功能你都实现好了吗？") and expects a requirement-by-requirement accounting that explicitly lists what is still not done and its limitations, rather than a summary that implies the whole set is finished. Confidence: 0.6
- When work involves merging/consolidating one UI element into another (e.g. folding a top progress bar into the per-bubble hint), asks whether any of the original states or flow were lost ("对应的状态你没有丢失吧？流程你没有丢失吧？") and expects a piece-by-piece parity accounting — every title, step, icon state and label from the removed component mapped to where it now appears, plus honest flagging of anything that genuinely can't be preserved — rather than a reassurance that "it's all fine". Confidence: 0.65
- Declines to supply context the agent could obtain on its own: when asked which machine a bug reproduced on, they answer "你看一下windows构建机的就知道了" — the expected default is that the agent goes and reads the build machine's logs and works it out itself rather than asking the user to identify the environment/timestamp. Confidence: 0.6
- Asks "为什么…" / "为什么要这么做" and expects a plain-language explanation of both the root cause and the design rationale behind a choice (including the trade-offs and alternative approaches, so they can pick one) before the work continues — not just a description of the fix ("为什么参数会混淆到提示词里面了", "为什么要上面多加一行"). Confidence: 0.6
