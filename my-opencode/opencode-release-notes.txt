- 修复视频无法落盘、客户端拿不到可播放地址的问题：下载上游视频产物时没有带供应商鉴权（返回 401），视频和封面都落不了盘，客户端只能退回中转站的临时链接、播放必然失败；现在下载媒体产物会带上与生视频请求一致的鉴权头
- 生视频轮询更稳：上游任务创建后短暂查不到（异步注册/索引延迟）时不再立刻判失败，在有限次数内继续等待；连续查不到才报错
- 生视频增加诊断日志：记录提交得到的任务标识与状态查询失败的上游响应，便于定位「Video request not found」这类上游问题
- 生成视频与首帧封面落成交付文件：客户端通过我们的下载通道在应用内播放，不再跳转上游中转站的临时地址（那种地址需要鉴权且会过期）
- 修复视频地址归一：上游返回的相对路径（/v1/videos/<id>/content）与已含 /v1 的 base 拼接会得到 /v1/v1/... 这类坏地址，现在按 URL 规则解析；已带协议（http/https/data）的地址原样保留
- 修复 FFmpeg 查找结果缓存：只缓存找到的结果，用户中途安装 FFmpeg 后下一次抽帧即可用，不必重启 agent
- 视频封面抽帧支持 launcher 托管的 FFmpeg：先查 PATH，再查 LAUNCHER_MANAGED_RUNTIME_DIR 下的 ffmpeg 安装目录，缺少时照常跳过封面
- 修复生视频结果被当成空正文的问题：视频此前不算作输出，任务会被判「模型未返回正文，本轮未产生可展示输出」，客户端也拿不到视频；现在视频与图片一样计入输出并随任务下发
- 修复视频生成失败时的报错不可读问题：上游返回 HTML 错误页（如 502）时不再抛出 JSON 解析错误，改为「上游返回了错误页面（HTTP xxx）」这类说明
- 修复未安装 ffmpeg 时视频封面抽帧报错、连带影响视频交付的问题：现在缺少 ffmpeg 或抽帧失败都直接跳过封面，视频照常返回；抽帧改为先下载视频再取帧，带鉴权的视频地址也能取到封面
- 修复生图 / 生视频模型被用于生成会话标题的问题：这类模型只有生成接口，过去会导致标题调用反复失败并报错，现在会跳过它们
- 修复配置里把生图 / 生视频模型的能力写成 text 输出、导致这类模型仍被当成对话模型的问题（请求走 chat 接口，上游直接报错）：名称带 image / video 的模型，输出模态以名称为准，不再被自动生成的能力配置覆盖
- 修复名称带 image / video 的模型在已知上下文窗口时未被识别成生图/生视频模型的问题：这类模型过去会走成普通对话（上游只提供生图接口，直接报错），现在无论是否已有窗口都按生图/生视频处理
- 生图与生视频参数改走会话消息的独立字段（不再从提示词文本解析）：提示词保持用户输入原样，历史重建与日志不再带出 --n=2 这类开关；旧客户端拼在文本里的参数仍兼容
- 新增视频生成：识别名字带 video 的模型，走 xAI 异步接口（提交拿 request_id、轮询状态、下载 MP4），支持时长（1-15 秒）、比例与分辨率参数
- 视频结果附首帧封面：用本机 ffmpeg 抽第一帧一并返回，客户端铺在播放卡片上；未装 ffmpeg 时不影响视频本身
- 生图多张可靠出图：n>1 时把请求归一成单张并发发出并聚合（中转站对 n 常只回 1 张），部分失败时仍交付成功张
- 目标支持继续执行：goal_resume 元数据带原 goal_id 与下一轮 iteration，从暂停轮次断点续跑（额度 = 原 max + 已跑轮数）；用户取消时目标正确落 paused 并下发 user_cancelled 原因
- 新增生图方言适配层：OpenAI 与 xAI Grok Imagine 按各自真实 API 参数构造请求，不再硬编码一套参数——OpenAI 按 gpt-image/dall-e 家族收窄 size/quality/format 并只为 gpt-image 发 moderation；xAI 用 aspect_ratio/resolution/quality，edits 走 JSON 且单多图用 image/images 不同字段
- 修复生图把所有会话内容拼进提示词的问题：生图是单轮请求只取本次用户输入，历史里的图片不会再误判成参考图，同一会话第二次生图不会带上上一轮要求
- 修复生图 `size` 与 `response_format` 无条件发送的问题：gpt-image-* 不再发 response_format（它永远返回 b64，发出去会被严格代理判非法参数）
- 修复 xAI Grok Imagine 无法生图的问题：命中方言即支持，不再用 npm 白名单；默认输出 jpeg
- 生图能力按模型下发给客户端，参数条只显示该模型真正认识的取值（OpenAI 显示尺寸、xAI 显示比例与分辨率）
- 供应商连接重试时目标不再显示为已暂停：paused 区分用户手动停止与连接重试，重试期间继续提示正在执行
- 修复被强杀的 git 留下 index.lock 后快照持续失败的问题：索引写入遇到锁冲突自动退避重试，超过 10 秒的陈旧锁自动清理后再重试
- 修复非媒体附件导致任务直接失败的问题：模型不支持的附件不再作为 file part 透传（OpenAI 兼容供应商会抛 UnsupportedFunctionalityError），文本内容改为内联，其他一律降级为中文提示
- 修复历史遗留的 application/octet-stream 文本附件持续污染会话、导致该会话后续每轮对话都失败的问题
- 附件无法映射成模型输入类型时不再放行，避免整个请求被供应商错误中断
- 修复任务完成结果选择逻辑：优先发送最终 assistant 回合正文，缺失时回退流式正文，不按长度或关键词裁剪用户内容
- 对话中的回复、同步、恢复和等待状态统一显示在正文下方的轻提示，不额外堆叠独立状态栏
- 活动任务历史按任务索引分页读取，避免恢复时扫描完整会话和子会话
- 完成事件与流式正文保持顺序，超大正文不会阻塞终态发送
- 修复快照误收录运行时数据库、构建缓存和大型生成文件导致 Git pack 无限膨胀的问题
- 清理快照前检查正式 pack 与松散对象的磁盘空间，空间不足时跳过 GC，避免再次生成巨型临时 pack
- 迁移旧快照索引时自动移除运行时文件和超限生成文件，仅修改快照索引，不删除工作区文件
- 活动任务使用索引分页恢复正文和工具历史，避免逐页重建完整会话及子会话
- 移除完整显示日志的常驻内存缓存，单任务历史读取按任务索引查询
- 保持正文、思考、工具、插入消息的顺序与持久化游标，兼容旧日志迁移
