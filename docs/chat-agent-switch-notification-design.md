# Agent 对话快捷切换与完成通知设计

## 1. 需求理解

- 在对话界面提供快捷切换到其他可用 Agent 对话的入口。
- 支持跨设备切换，不复用当前对话页面的状态。
- 目标对话使用目标设备、Agent、项目和项目作用域的完整路由参数重新进入。
- 任务完成后生成应用内通知。
- 通知提供进入完成 Agent 对话界面的快捷按钮。
- 只展示可用 Agent：设备在线、Agent 已启用、项目绑定有效。
- 通知和切换流程需要覆盖移动端与桌面端。

## 2. 假设与约束

- `machineId`、`agentId`、`projectId`、`projectScopeId` 和 `projectRoot` 可以构成完整对话入口。
- 当前通知系统已经支持同步通知、通知中心和 `openRoute` 操作。
- 当前后端任务完成事件可以取得任务的设备、Agent、项目和会话信息。
- Agent 详情列表是切换面板的可用性来源。
- 用户不需要在切换前确认；点击可用 Agent 即执行切换。

## 3. 总体方案

采用统一的 Agent 目标模型和完整路由跳转：

1. 对话页加载可用 Agent 目标列表。
2. 顶部上下文栏提供“切换 Agent”入口。
3. 面板按设备分组展示 Agent，并支持搜索。
4. 点击目标后替换当前对话路由。
5. 目标对话页独立加载会话、模型、项目上下文和项目记忆。
6. 后端在任务完成时生成同步应用通知。
7. 通知通过 `openRoute` 操作跳转到目标对话。

## 4. Agent 目标模型

新增统一的 `ChatTarget` 数据模型，至少包含：

```text
machineId
agentId
projectId
projectScopeId
projectRoot
deviceName
agentName
projectName
online
enabled
projectAvailable
```

可用条件：

```text
device.online == true
agent.enabled == true
agent.isOnline == true
projectId 非空
projectScopeId 或有效项目绑定存在
```

切换列表使用设备列表数据派生目标，不直接复用当前 `ChatState`。目标列表需要包含加载、空数据和请求失败状态。

## 5. 快捷切换交互

### 桌面端

- 在对话页顶部上下文栏增加切换图标按钮。
- 点击后打开锚定面板。
- 面板按设备分组展示可用 Agent。
- 每项显示设备名称、Agent 名称和项目名称。
- 当前目标显示选中状态。
- 目标数量较多时提供实时搜索。

### 移动端

- 使用同一个切换图标入口。
- 点击后打开底部抽屉。
- 抽屉顶部提供搜索框。
- 设备分组和 Agent 项保持与桌面端一致。
- 面板内部独立滚动，不改变当前对话页面布局。

### 路由行为

目标路由必须完整携带：

```text
machineId
agentId
projectId
projectScopeId
projectRoot
```

切换使用路由替换，避免多次切换后返回栈不断增长。目标页面重新创建或刷新自己的 Provider 状态。

## 6. 完成通知

任务完成时由后端生成同步应用通知，避免用户离开当前页面或任务在其他设备执行时漏通知。

通知建议结构：

```text
operationId: chat-task:<taskId>
kind: agent
scope: synced
status: succeeded
title: <Agent名称> · 任务已完成
message: <项目名称> · <任务摘要>
```

通知主操作：

```text
label: 查看对话
type: openRoute
```

操作 payload 使用完整目标对话路由。点击后关闭通知浮层或通知中心，标记通知已读，再跳转到目标对话。

## 7. 通知显示策略

- 当前对话页完成：显示紧凑通知卡片，并提供“回到结果”操作。
- 其他 Agent 或设备完成：显示 Agent、设备和项目名称，提供“查看对话”。
- 用户已经位于目标对话页：不重复堆叠页面，刷新消息并滚动到最新回复。
- 同一任务重复事件：通过 `operationId` 幂等处理。
- 通知路由参数过期：跳转到目标设备详情页，并提示项目或 Agent 状态已变化。

## 8. 边界与错误处理

- 设备列表加载中显示骨架项。
- 没有可用 Agent 显示空状态。
- 目标 Agent 点击后离线时保留当前页面并提示不可用。
- 目标项目绑定变化时重新读取最新项目作用域。
- 目标 Agent 没有历史会话时进入空白对话页，允许直接发送。
- 通知跳转失败时保留通知，允许用户再次点击。
- 当前页面仍保持可用时，不因切换列表请求失败而阻塞当前对话。

## 9. 测试策略

- 多设备、多 Agent 的分组、过滤和搜索。
- 切换后完整校验 `machineId`、`agentId`、`projectId` 和 `projectScopeId`。
- 切换不会复用旧 `ChatState`、模型列表或项目记忆状态。
- 任务完成事件只生成一条同步通知。
- 通知按钮可以打开正确的目标对话。
- 当前对话完成、跨设备完成、重复事件和失效路由参数。
- 移动端底部抽屉和桌面端锚定面板的布局测试。
- 离线、禁用 Agent、无项目绑定和请求失败状态。

## 10. 决策记录

| 决策 | 选择 | 原因 |
| --- | --- | --- |
| 切换范围 | 所有可用设备中的 Agent | 满足跨设备切换需求，避免限制在当前设备 |
| 切换数据 | 统一 `ChatTarget` | 防止设备、Agent、项目参数在多个 Widget 中重复拼装 |
| 切换方式 | 完整路由替换 | 避免复用旧对话状态和返回栈膨胀 |
| 移动端入口 | 底部抽屉 | 适合跨设备 Agent 列表和搜索操作 |
| 桌面端入口 | 锚定面板 | 保持上下文栏紧凑，不遮挡主对话 |
| 通知来源 | 后端任务完成事件 | 页面关闭或跨设备完成时仍能生成通知 |
| 通知同步 | 使用现有 synced 通知机制 | 复用通知中心、持久化和去重能力 |
| 通知跳转 | `openRoute` 直接进入对话 | 减少中间页面，符合用户查看完成结果的目标 |
| 通知幂等 | `chat-task:<taskId>` | 避免本地事件、同步和推送重复展示 |

## 11. 非目标

- 本功能不改变 Agent 的任务执行逻辑。
- 本功能不改变模型选择规则。
- 本功能不把多个 Agent 的会话合并到同一个聊天状态。
- 本功能不展示离线或项目绑定失效的 Agent。
- 本功能不在通知中展示完整回复内容。
