# 后端模块设计

## 目标

构建一个稳定、低损耗、便于远程控制的后端控制中心，负责：

- 管理多台机器的在线状态
- 管理每台机器上的多个 `agent`
- 将任务按 `agent_id` 精确转发给对应的 `OpenCode serve`
- 保存任务、审批、事件流、会话映射

推荐架构：

```text
移动端 / Web
-> 后端控制中心（Go）
-> Agent Broker（WebSocket）
-> 多个 OpenCode serve
-> 本地代码仓库 / shell / MCP
```

## 模块划分

### 1. 接入层模块

职责：

- 对外提供 `HTTPS API`
- 提供任务创建、查询、审批、取消、agent 列表查询
- 提供任务事件流查询入口

第一阶段接口：

- `GET /api/agents`
- `POST /api/tasks`
- `GET /api/tasks/:taskId`
- `GET /api/tasks/:taskId/events`
- `POST /api/tasks/:taskId/cancel`
- `POST /api/tasks/:taskId/approval`

实现要点：

- 创建任务必须显式传 `agent_id`
- 不做自动调度
- 外部调用先走 HTTP，事件流先走 `SSE`

### 2. Agent 连接模块

职责：

- 维护 `agent` 与服务器的长连接
- 管理上线、下线、心跳、重连
- 维护 `agent -> websocket` 映射

实现要点：

- 同一 `agent_id` 只保留一个活跃连接
- `machine_id` 与 `agent_id` 分开建模
- 心跳时同步 `current_task_id`

关键细节：

- `agent_id` 是调度最小单位
- 一个 `agent` 对应一个项目执行上下文
- 同一物理机器可以挂多个 `agent`

### 3. 任务调度模块

职责：

- 接收用户任务
- 检查目标 `agent` 是否在线
- 检查目标 `agent` 是否拥有对应项目
- 将任务转发给目标 `agent`

任务状态：

- `pending`
- `dispatched`
- `running`
- `waiting_approval`
- `completed`
- `failed`
- `cancelled`

第一阶段策略：

- 只支持按 `agent_id` 投递
- 一个 `agent` 内部串行
- 多个 `agent` 之间并发

### 4. 会话管理模块

职责：

- 保证同一对话持续复用同一个 `OpenCode session`
- 维护外部任务与内部 `session_id` 的映射关系

核心字段：

- `session_id`
- `agent_id`
- `machine_id`
- `project_id`
- `last_task_id`
- `status`

关键细节：

- 会话绑定的是 `agent`，不是 `machine`
- 不能把 `project-a` 的会话拿去 `project-b` 复用

### 5. 审批与安全模块

职责：

- 接收 `agent` 上报的高风险操作审批请求
- 后端挂起任务并等待人工决策
- 审批后恢复执行

关键细节：

- 审批对象属于任务，但执行上下文属于 `agent`
- 审批通过后仍然必须回到原 `agent` 继续执行

### 6. 存储模块

职责：

- 持久化 `machines`
- 持久化 `agents`
- 持久化 `tasks`
- 持久化 `task_events`
- 持久化 `sessions`
- 持久化 `task_approvals`

第一阶段内存版至少要有：

- 在线 `agent` 列表
- 任务信息
- 事件流

后续数据库建议表：

- `machines`
- `agents`
- `tasks`
- `task_events`
- `sessions`
- `task_approvals`

### 7. 观测与运维模块

职责：

- 观察在线 `agent`
- 观察每个 `machine` 上的 `agent` 分布
- 记录任务耗时、失败率、审批次数

## 第一阶段落地顺序

1. 将后端调度主键从 `device_id` 改成 `agent_id`
2. `device.hello` 扩展为携带 `machine_id + agent_id`
3. 增加 `GET /api/agents`
4. 创建任务时校验 `agent` 在线且拥有该项目
5. 任务记录 `machine_id` 与 `project_root`
6. 审批、取消、状态回传全部按 `agent_id` 路由

## 当前不做的事情

- 不做自动选 agent
- 不做任务在多个 agent 之间迁移
- 不做按 machine 维度的调度策略
- 不做 agent 分组、优先级、负载均衡

## 设计原则

- 后端调度单位固定为 `agent`
- `machine` 只是宿主，不直接接任务
- 一个 `agent` 保持串行执行，稳定优先于吞吐
