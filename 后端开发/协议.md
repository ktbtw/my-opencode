# 后端协议设计

## 目标

定义后端控制中心与执行端之间的多机多 `agent` 第一版协议。

这里明确区分两个概念：

- `machine`：物理设备或云主机，例如 `macbook-main`、`srv-beijing-01`
- `agent`：某个项目目录下的独立执行实例，例如 `macbook-main:project-a`

后端调度最小单位是 `agent`，不是 `machine`。

协议目标：

- 支持多机在线
- 支持同一台机器挂多个 `agent`
- 支持任务按 `agent_id` 精确投递
- 支持流式输出、审批、取消、完成、失败
- 支持同一 `session_id` 持续复用
- 支持文本、图片、PDF、普通文件等多模态输入

## 通信通道

### 1. 外部 API

- 协议：`HTTPS`
- 用途：移动端 / Web 调用后端

### 2. Agent 连接

- 协议：`WebSocket`
- 路径：`/ws/device`
- 用途：各个 `agent` 主动连接后端并保持长连接

说明：

- 路径暂时仍沿用 `/ws/device`
- 语义上已经是 `agent websocket`

## 核心模型

### Machine

建议字段：

- `machine_id`
- `hostname`
- `last_seen`

### Agent

建议字段：

- `agent_id`
- `machine_id`
- `project_id`
- `project_root`
- `status`
- `current_task_id`

## HTTP API 设计

### `GET /api/agents`

用途：

- 查询当前在线 `agent` 列表

响应示例：

```json
[
  {
    "agent_id": "macbook-main:project-a",
    "machine_id": "macbook-main",
    "hostname": "MacBook-Pro",
    "version": "0.1.0",
    "projects": [
      {
        "project_id": "project-a",
        "root": "/Users/yuminghao/project-a"
      }
    ],
    "seen_at": "2026-04-04T00:00:00Z",
    "current_task_id": ""
  }
]
```

### `POST /api/tasks`

用途：

- 创建一个新任务或继续一个已有会话

请求体：

```json
{
  "agent_id": "macbook-main:project-a",
  "project_id": "project-a",
  "parts": [
    {
      "type": "text",
      "text": "请修复登录接口报错"
    },
    {
      "type": "file",
      "mime": "image/png",
      "filename": "login-error.png",
      "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
    }
  ],
  "session_id": "sess_123",
  "metadata": {
    "branch": "feature/login-fix"
  }
}
```

字段说明：

- `agent_id`：目标执行器
- `project_id`：目标项目
- `parts`：必填字段。顺序保留，直接对齐 `opencode PromptInput.parts`
- `session_id`：可选。传入时表示继续已有会话
- `metadata`：可选扩展字段

说明：

- 不再接受 `device_id`
- `parts` 为唯一输入字段
- 当前支持 `text`、`file`、`agent`、`subtask`
- 图片、PDF、普通文件统一走 `file part`

响应：

```json
{
  "task_id": "task_123",
  "agent_id": "macbook-main:project-a",
  "machine_id": "macbook-main",
  "project_id": "project-a",
  "project_root": "/Users/yuminghao/project-a",
  "session_id": "sess_123",
  "status": "dispatched",
  "parts": [
    {
      "type": "text",
      "text": "请修复登录接口报错"
    }
  ]
}
```

### `GET /api/tasks/:taskId`

用途：

- 查询任务当前状态

响应示例：

```json
{
  "task_id": "task_123",
  "agent_id": "macbook-main:project-a",
  "machine_id": "macbook-main",
  "project_id": "project-a",
  "project_root": "/Users/yuminghao/project-a",
  "session_id": "sess_123",
  "status": "running",
  "result": "",
  "error": "",
  "created_at": "2026-04-04T00:00:00Z",
  "updated_at": "2026-04-04T00:00:05Z"
}
```

### `GET /api/tasks/:taskId/events`

用途：

- 通过 `SSE` 订阅任务事件流

### `POST /api/tasks/:taskId/cancel`

用途：

- 请求取消某个任务

### `POST /api/tasks/:taskId/approval`

用途：

- 对处于 `waiting_approval` 状态的任务提交审批结果

请求体：

```json
{
  "permission_id": "permission_123",
  "reply": "once",
  "message": ""
}
```

字段说明：

- `permission_id`：可选。不传时默认使用任务当前挂起的审批项
- `reply`：必填，支持 `once`、`always`、`reject`
- `message`：可选，拒绝时可附带说明

## WebSocket 消息设计

所有消息统一格式：

```json
{
  "type": "task.run",
  "request_id": "req_123",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {}
}
```

## Agent 上线消息

### `device.hello`

虽然消息名仍为 `device.hello`，但语义已经改成 `agent hello`。

```json
{
  "type": "device.hello",
  "request_id": "req_hello_1",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {
    "agent_id": "macbook-main:project-a",
    "machine_id": "macbook-main",
    "hostname": "MacBook-Pro",
    "version": "0.1.0",
    "projects": [
      {
        "project_id": "project-a",
        "root": "/Users/yuminghao/project-a"
      }
    ]
  }
}
```

字段说明：

- `agent_id`：当前执行器唯一标识
- `machine_id`：执行器所属机器
- `projects`：当前执行器允许操作的项目列表

## 服务端欢迎消息

### `device.welcome`

```json
{
  "type": "device.welcome",
  "request_id": "req_hello_1",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {

```

## 当前边界

当前版本明确采用以下策略：

- 一个 `agent` 一次只执行一个任务
- 多个 `agent` 之间可以并发
- 后端只支持按 `agent_id` 精确投递
- 暂不支持“按 machine 自动选择空闲 agent”
- 暂不支持任务跨 `agent` 自动迁移
