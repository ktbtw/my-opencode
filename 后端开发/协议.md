# 后端协议设计

## 目标

定义后端控制中心与设备端之间的第一版通信协议，用于支撑以下链路：

```text
移动端 / Web
-> 后端 HTTP API
-> 后端 WebSocket broker
-> 设备端（改造后的 OpenCode serve）
-> 结果流式回传
```

第一版目标：

- 单设备在线
- 单项目串行执行
- 支持任务创建、取消、流式输出、完成、失败
- 支持同一 `session_id` 持续复用
- 支持文本、图片、PDF、普通文件等多模态输入

## 通信通道

### 1. 外部 API

- 协议：`HTTPS`
- 用途：移动端与 Web 调用后端

### 2. 设备连接

- 协议：`WebSocket`
- 路径：`/ws/device`
- 用途：设备主动连接后端并保持长连接

## HTTP API 设计

### `POST /api/tasks`

用途：

- 创建一个新任务或继续一个已有会话

请求体：

```json
{
  "device_id": "macbook-main",
  "project_id": "chat-codex",
  "parts": [
    {
      "type": "text",
      "text": "请结合这张图片继续修复登录接口报错"
    },
    {
      "type": "file",
      "mime": "image/png",
      "filename": "login-error.png",
      "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
    }
  ],
  "session_id": "sess_123",
  "metadata": {
    "branch": "feature/relay"
  }
}
```

字段说明：

- `device_id`：目标设备
- `project_id`：目标项目
- `parts`：必填字段。顺序保留，直接对齐 `opencode PromptInput.parts`
- `session_id`：可选。传入时表示继续已有会话
- `metadata`：可选扩展字段

说明：

- `parts` 为唯一输入字段
- 当前支持 `text`、`file`、`agent`、`subtask`
- 图片、PDF、普通文件统一走 `file part`

响应：

```json
{
  "task_id": "task_123",
  "device_id": "macbook-main",
  "project_id": "chat-codex",
  "session_id": "sess_123",
  "status": "dispatched",
  "parts": [
    {
      "type": "text",
      "text": "请结合这张图片继续修复登录接口报错"
    },
    {
      "type": "file",
      "mime": "image/png",
      "filename": "login-error.png",
      "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
    }
  ]
}
```

### `GET /api/tasks/:taskId`

用途：

- 查询任务当前状态

响应：

```json
{
  "task_id": "task_123",
  "device_id": "macbook-main",
  "project_id": "chat-codex",
  "session_id": "sess_123",
  "status": "running",
  "parts": [
    {
      "type": "text",
      "text": "请结合这张图片继续修复登录接口报错"
    }
  ],
  "result": "",
  "error": "",
  "created_at": "2026-04-04T00:00:00Z",
  "updated_at": "2026-04-04T00:00:05Z"
}
```

### `GET /api/tasks/:taskId/events`

用途：

- 通过 `SSE` 订阅任务事件流

事件格式：

```text
event: delta
data: {"task_id":"task_123","content":"正在分析项目结构"}
```

当前服务端会保留任务生命周期内的事件记录，便于补拉和调试：

- `dispatched`
- `started`
- `delta`
- `completed`
- `failed`
- `cancelled`

### `POST /api/tasks/:taskId/cancel`

用途：

- 请求取消某个任务

响应：

```json
{
  "task_id": "task_123",
  "status": "cancelled"
}
```

## WebSocket 消息设计

所有消息统一格式：

```json
{
  "type": "task.run",
  "request_id": "req_123",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {}
}
```

字段说明：

- `type`：消息类型
- `request_id`：请求链路唯一标识
- `sent_at`：发送时间
- `payload`：业务载荷

## 设备上线消息

### `device.hello`

设备连接成功后第一条消息必须发送：

```json
{
  "type": "device.hello",
  "request_id": "req_hello_1",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {
    "device_id": "macbook-main",
    "hostname": "MacBook-Pro",
    "version": "0.1.0",
    "projects": [
      {
        "project_id": "chat-codex",
        "root": "/Users/yuminghao/Downloads/chat-codex"
      }
    ]
  }
}
```

服务端返回：

### `device.welcome`

```json
{
  "type": "device.welcome",
  "request_id": "req_hello_1",
  "sent_at": "2026-04-04T00:00:00Z",
  "payload": {
    "device_id": "macbook-main",
    "heartbeat_interval_sec": 15
  }
}
```

## 任务下发消息

### `task.run`

服务端发给设备：

```json
{
  "type": "task.run",
  "request_id": "req_task_1",
  "sent_at": "2026-04-04T00:00:20Z",
  "payload": {
    "task_id": "task_123",
    "device_id": "macbook-main",
    "project_id": "chat-codex",
    "session_id": "sess_123",
    "parts": [
      {
        "type": "text",
        "text": "请结合这张图片继续修复登录接口报错"
      },
      {
        "type": "file",
        "mime": "image/png",
        "filename": "login-error.png",
        "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
      }
    ],
    "metadata": {
      "branch": "feature/relay"
    }
  }
}
```

字段说明：

- `task_id`：任务唯一标识
- `session_id`：为空表示新会话，不为空表示继续
- `parts`：实际输入内容，设备端直接使用
- `metadata`：设备执行时的额外上下文

## `parts` 结构

后端 `parts` 直接镜像 `opencode` 的输入结构，当前支持以下 4 种类型。

### `text`

```json
{
  "type": "text",
  "text": "请只回复 ok"
}
```

### `file`

```json
{
  "type": "file",
  "mime": "image/png",
  "filename": "screen.png",
  "url": "data:image/png;base64,iVBORw0KGgoAAAANSUhEUgAA..."
}
```

可选的 `source` 也可以直接透传，例如：

```json
{
  "type": "file",
  "mime": "text/plain",
  "filename": "README.md",
  "url": "data:text/plain;base64,SGVsbG8=",
  "source": {
    "type": "file",
    "path": "/Users/yuminghao/Downloads/chat-codex/README.md",
    "text": {
      "value": "@README.md",
      "start": 0,
      "end": 9
    }
  }
}
```

### `agent`

```json
{
  "type": "agent",
  "name": "worker",
  "source": {
    "value": "@worker",
    "start": 0,
    "end": 7
  }
}
```

### `subtask`

```json
{
  "type": "subtask",
  "prompt": "检查最近的变更并修复测试",
  "description": "修复测试",
  "agent": "worker",
  "model": {
    "providerID": "xcodebest",
    "modelID": "xcodebest/gpt-5.4-mini"
  },
  "command": "task"
}
```

约束：

- `file.url` 当前推荐直接使用 `data:` URL，设备端可直接透传给 OpenCode
- `mime` 建议明确填写，例如 `image/png`、`image/jpeg`、`application/pdf`
- `file.source` 支持 `file`、`symbol`、`resource`
- 未来如需传本地文件引用或对象存储链接，可在第二版协议继续扩展

## 状态约束

### 任务状态

- `pending`
- `dispatched`
- `running`
- `completed`
- `failed`
- `cancelled`

### 状态转换

```text
pending -> dispatched -> running -> completed
pending -> dispatched -> running -> failed
pending -> cancelled
dispatched -> cancelled
running -> cancelled
```

## 第一版约束

- 单设备同一时刻只允许一个运行中任务
- 单项目同一时刻只允许一个运行中任务
- `session_id` 必须由设备端最终确认并回传
- 任务事件按时间顺序落库

## 第二版预留

- `task.approval_required`
- `task.approval_response`
- 多设备调度
- 项目级权限
- 二进制协议或 protobuf
